# 커밋 스킬

변경사항을 분석하고 논리적 단위로 분류하여 컨벤션에 맞는 한국어 커밋 메시지로 커밋합니다.

## 절차

### 1단계: 변경사항 분석
먼저 현재 변경사항을 확인합니다:
- `git status`로 수정된 파일 목록 확인
- `git diff`로 각 파일의 구체적 변경사항 분석
- `git log --oneline -5`로 최근 커밋 메시지 스타일 확인

### 2단계: 논리적 단위로 분류
변경사항을 다음 카테고리로 분류합니다:

- **feat**: 새로운 기능 추가
- **fix**: 버그 수정
- **refactor**: 코드 리팩토링 (기능 변화 없음)
- **style**: 포맷팅, 띄어쓰기, 세미콜론 등
- **chore**: 빌드, 패키지, 의존성 등의 변경

### 3단계: 커밋 메시지 작성
**형식**: `타입: 요약 (한국어)`

규칙:
- **첫 문자 대문자**: 한국어는 자연스럽게
- **50자 이내**: 요약은 간결하게
- **명령조 사용**: "추가함" → "추가" (필요시)
- **현재형 기준**: "변경했습니다" → "변경합니다"

**예시**:
- `feat: 레트로 디자인 컬러 팔레트 적용`
- `fix: 헤더 타이포그래피 정렬 오류 수정`
- `refactor: 버튼 스타일링 CSS 통합`
- `chore: 개발 서버 포트 설정 변경`

### 4단계: 사용자 승인
제안된 커밋 메시지를 사용자에게 표시하고 승인을 요청합니다:
- "이 메시지로 커밋할까요?" → 승인
- 필요시 메시지 수정 제안

### 5단계: 커밋 실행
```bash
git add <files>
git commit -m "메시지"
git status  # 커밋 확인
```

## 주의사항

✅ **할 것**:
- 관련 파일들을 논리적 단위로 그룹화
- 명확하고 설명적인 메시지 작성
- 한 커밋에는 하나의 주요 변경사항만
- 반드시 사용자 승인 후 커밋

❌ **하지 말 것**:
- git add -A로 무분별하게 스테이징
- 비밀 정보나 환경변수 포함
- 너무 광범위한 변경을 한 커밋에

## 사용 예시

```
사용자: 커밋해줘
assistant: 변경사항을 분석하겠습니다...

분석 결과:
📝 src/App.css - 컬러 변수 및 스타일 변경
📝 src/index.css - 배경 그레이디언트 추가

제안 커밋 메시지:
✨ feat: 레트로 1970s 디자인 테마 적용

→ 이 메시지로 커밋할까요?
```
